# Decision Log

## Decision

- 제목: Git 이력 제목, 커밋 메시지, 브랜치 이름 기본 포맷 명시
- 날짜: 2026-03-11
- 상태: accepted

## Context

- Git commit workflow는 staged diff 기반 초안 작성과 브랜치 안전성 확인을 정의하고 있었다.
- 하지만 이력 제목, 커밋 메시지, 브랜치 이름의 형식은 명시하지 않아 세션마다 표현이 흔들릴 여지가 있었다.
- 또한 staged diff 기준으로 이력 내용까지 제안한다는 규칙이 빠져 있어 검토 흐름이 완결되지 않았다.
- 이력 내용을 어떤 형태로 제안할지도 정해져 있지 않아 응답 형식이 다시 흔들릴 수 있었다.
- 이력 제목도 일반 텍스트로만 제안하면 사용자가 복사하기 불편할 수 있었다.
- 이력번호를 AI가 임의로 채우면 사용자가 확정해야 할 범위를 침범하게 된다.

## Options Considered

1. 기존처럼 예시만 두고 포맷은 사용자가 매번 정한다.
2. 이력 제목, 이력 내용, 커밋 메시지, 브랜치 이름 기본 포맷을 workflow에 명시한다.
3. 포맷 대신 카테고리 목록만 정의한다.

## Decision

- 옵션 2를 채택한다.
- 이력 제목은 `[주제 or 카테고리] 제목` 형식을 사용한다.
- 이력 제목은 사용자에게 코드 블록 안에 담아 제안한다.
- 이력 내용은 staged diff 기준 핵심 변경 bullet 요약 형식을 사용한다.
- 이력 내용은 사용자에게 코드 블록 안에 담아 제안한다.
- 커밋 제목은 `[#이력번호] 이력번호에 해당하는 제목과 동일` 형식을 사용한다.
- 브랜치 이름은 `이력번호-이력제목 영문 소문자 slug` 형식을 사용한다.
- 브랜치 분류용 접두어는 사용하지 않는다.
- 이력번호는 사용자 확정 전까지 AI가 임의로 채우지 않고 자리표시자로만 제안한다.

## Consequences

- 장점:
- 이력, 커밋, 브랜치 이름의 관계가 명확해진다.
- 새 대화나 새 세션에서도 같은 패턴으로 초안을 만들기 쉬워진다.
- staged diff 기준 이력 내용까지 함께 검토할 수 있어 커밋 전 확인 흐름이 완결된다.
- 이력 제목도 코드 블록으로 제안해 바로 복사해 쓰기 쉬워진다.
- 이력 내용을 코드 블록으로 제안해 복사와 검토가 쉬워진다.
- 이력번호를 섣불리 고정하지 않아 사용자 검토 흐름을 보존할 수 있다.
- 단점:
- 프로젝트마다 선호하는 카테고리 체계와 slug 변환 방식은 별도로 조정해야 할 수 있다.
- 후속 작업:
- 한글 제목을 영문 slug로 바꾸는 예시가 더 필요하면 예시 문서를 보강한다.
