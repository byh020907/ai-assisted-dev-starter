# Project Init Scenario

## 목적

이 문서는 사람이 새 프로젝트를 시작할 때, AI 에이전트와 어떤 흐름으로 프로젝트 문서와 작업 구조를 잡아갈 수 있는지 보여주는 시나리오 예시다.

## 시나리오

개발자가 새 프로젝트를 시작하면서 AI 에이전트에게 이렇게 요청한다.

> 팀 메모를 저장하고 조회하는 내부용 API 프로젝트를 시작하려고 해.
> 이 저장소 규칙에 맞춰 기본 문서 구조부터 잡아줘.

AI 에이전트는 저장소의 `AGENTS.md`, `ai/` 문서, `docs/` 구조를 먼저 확인한 뒤,
프로젝트 시작에 필요한 기본 문서를 정리한다.

이때 `PROJECT_BRIEF`는 사람이 직접 처음부터 길게 작성하는 문서라기보다,
AI 에이전트가 필요한 정보만 먼저 질문하고 그 답을 바탕으로 초안을 채우는 문서로 사용한다.

예를 들어 AI 에이전트는 아래 정도를 먼저 확인한다.

- 이 프로젝트를 한 줄로 설명하면 무엇인지
- 어떤 문제를 해결하려는지
- 이번 단계에서 꼭 만들 것은 무엇인지
- 이번 단계에서 하지 않을 것은 무엇인지
- 주요 대상 사용자는 누구인지
- 성공 기준은 무엇인지
- 제약사항이나 가정은 무엇인지

## 이 요청 이후 생기는 문서

```text
+docs/project/
+|-- brief.md
+docs/tasks/20260311-create-note-api/
+|-- task.md
+|-- worklog.md
+`-- decision.md
```

## 각 문서가 생기는 이유

### 1. 프로젝트 상위 문서

사용자는 먼저 프로젝트 목적과 범위를 정리하고 싶어 한다.
그래서 AI 에이전트는 `docs/project/brief.md`를 만든다.

이 문서에는 보통 아래 내용이 들어간다.

- 프로젝트 한 줄 설명
- 해결하려는 문제
- 이번 단계 목표
- 제외 범위
- 주요 사용자 또는 대상
- 성공 기준
- 제약사항 / 가정

프로젝트가 진행되면 `docs/project/` 아래에 도메인 개요나 용어집 같은 상위 문서를 더 추가할 수도 있다.

### 2. 첫 작업 문서

사용자가 “우선 메모 생성 API부터 만들자”라고 정하면,
AI 에이전트는 첫 작업 디렉토리 `docs/tasks/20260311-create-note-api/`를 만들고 그 안에 `task.md`를 둔다.

이 문서에는 보통 아래가 들어간다.

- 작업명
- 배경
- 목표
- 완료 조건
- 범위

### 3. 작업 기록 문서

개발이 진행되면 사용자는 중간 판단과 확인 사항도 남기고 싶어 한다.
그래서 같은 디렉토리 안의 `worklog.md`에 아래 같은 내용을 기록한다.

- 오늘 무엇을 확인했는지
- 어떤 가정을 두고 진행했는지
- 아직 보류 중인 것은 무엇인지
- 다음에 이어서 할 일은 무엇인지

### 4. 작업 단위 결정 문서

구현하다 보면 "이 작업 안에서 중요한 선택"이 생긴다.
예를 들어 저장 방식, 상태값, 응답 형식 같은 것들이다.
이런 내용은 같은 디렉토리 안의 `decision.md`에 남긴다.

## 이 시나리오가 보여주는 점

이 저장소에서는 사람이 요청하고, AI 에이전트는 현재 프로젝트 지침을 참고해 필요한 문서 구조를 먼저 만든다.
그리고 프로젝트 전체 문서는 `docs/project/`에,
개별 작업 문서는 `docs/tasks/<date>-<task-slug>/` 아래에 정리한다.

그래서 사람 입장에서는 아래가 쉬워진다.

- 프로젝트 전체 배경과 현재 작업을 구분해서 보기
- 특정 작업의 맥락을 한 번에 파악하기
- 나중에 작업 흐름을 다시 따라가기

## ADR은 언제 쓰는가

위의 `decision.md`는 작업 안에서 나온 선택을 기록하는 문서다.
반면 프로젝트 전체 기준을 바꾸는 장기 결정은 `docs/adr/`에 기록한다.
