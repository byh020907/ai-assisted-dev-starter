# Project-Specific AI Rules Scenario

## 목적

이 문서는 프로젝트마다 달라질 수 있는 AI 협업 스타일을 공통 규칙과 분리해 관리하는 상황을 사람 관점에서 보여주는 시나리오 예시다.

## 시나리오

어떤 팀은 AI가 항상 한국어로 답해주길 원하고,
어떤 팀은 구현 전에 방법을 먼저 제안해주길 원한다.
또 어떤 팀은 복잡한 코드 변경에만 설명 주석을 남기길 선호한다.

개발팀은 이런 요구가 유용하다고 느끼지만,
모든 프로젝트에 공통으로 강제할 기준은 아니라는 점도 함께 인식한다.

그래서 팀은 AI 에이전트에게 이렇게 요청한다.

> 이 팀에서만 쓰는 AI 협업 스타일을 따로 정리해줘.
> 공통 규칙 문서와는 분리하고 싶어.

## 이 요청 이후 달라지는 점

AI 에이전트는 프로젝트 전체에 적용되는 문서 위치인 `docs/project/` 아래에
`ai-collaboration.md` 같은 문서를 만들고, 팀의 선호를 그 문서에 정리한다.

예를 들어 아래 같은 항목이 들어갈 수 있다.

- 기본 응답 언어는 한국어로 유지한다.
- 구현 전에 가능한 방법이나 선택지를 먼저 제안한다.
- 복잡한 변경에는 짧은 설명 주석이나 문서 기록을 남긴다.

반면 아래 같은 내용은 공통 규칙으로 유지한다.

- 요청이 모호하면 선택지로 범위를 좁힌다.
- 기술 스택은 진입 파일을 먼저 보고 판단한다.
- 마크다운 다이어그램은 Mermaid를 우선 사용한다.

## 사람 입장에서 이 시나리오가 중요한 이유

이렇게 분리해두면 팀은 자기 스타일을 문서화할 수 있고,
공통 스타터 저장소는 특정 팀 취향으로 과하게 기울지 않는다.

사람은 아래 이점을 얻는다.

- 프로젝트별 선호를 명확히 관리할 수 있다.
- 공통 규칙 문서가 불필요하게 비대해지지 않는다.
- 팀이 바뀌어도 공통 규칙과 프로젝트 규칙의 경계를 쉽게 이해할 수 있다.

## 이 시나리오가 보여주는 기준

- 팀별 선호와 협업 스타일은 `docs/project/` 아래 프로젝트 문서로 관리한다.
- 여러 프로젝트에 반복 적용되는 기준만 `ai/standards/`나 `ai/workflows/`로 승격한다.
