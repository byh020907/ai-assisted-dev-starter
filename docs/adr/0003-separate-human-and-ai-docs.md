# ADR 0003: Separate Human Docs and AI Operational Docs

- Status: accepted
- Date: 2026-03-11

## Context

이 저장소는 사람이 읽는 설명 문서와 AI가 작업 중 직접 참조하는 운영 문서를 함께 다루고 있다.
초기 구조를 정리하는 과정에서, 같은 경로 아래에 사람용 문서와 AI용 규칙/템플릿을 섞어 둘지,
아니면 역할에 따라 분리할지 결정이 필요했다.

사람은 저장소 목적, 예시 시나리오, ADR 같은 설명 중심 문서를 읽고,
AI는 작업 분류, workflow, 템플릿 같은 실행 중심 문서를 우선 참조해야 한다.
이 둘이 같은 위치에 섞이면 우선순위가 흐려지고, 문서 역할도 모호해질 수 있다.

## Options Considered

1. 사람용 문서와 AI용 문서를 같은 디렉토리 아래에 함께 둔다.
2. 사람용 문서는 `docs/`, AI용 운영 문서는 `ai/`로 분리한다.
3. 문서 종류마다 흩어 배치하고 도구가 문맥으로만 판단하게 둔다.

## Decision

사람용 문서는 `docs/`에 두고, AI가 직접 참조하는 운영 문서는 `ai/`로 분리한다.

구체적으로:

- `docs/`: 사람이 읽는 설명, 예시 시나리오, ADR
- `ai/standards/`: 작업 분류와 관례
- `ai/workflows/`: 작업 흐름
- `ai/templates/`: 문서 초안 템플릿
- `AGENTS.md`: AI가 가장 먼저 읽는 인덱스 문서

## Consequences

- Positive:
  - 사람용 문서와 AI용 문서의 역할이 더 분명해진다.
  - AI가 규범 문서를 우선 참조하기 쉬워진다.
  - 예시 문서와 실행 규칙이 섞여 생기는 혼동을 줄일 수 있다.
- Negative:
  - 문서가 여러 위치로 나뉘어 처음에는 구조를 익혀야 한다.
  - 중복 설명이 생기지 않도록 인덱스와 참조 관계를 계속 관리해야 한다.
- Follow-up:
  - `AGENTS.md`는 짧은 인덱스로 유지한다.
  - `docs/examples/`는 사람 관점의 시나리오 예시만 둔다.
