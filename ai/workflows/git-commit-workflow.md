# Git Commit Workflow

## 목적

이 문서는 사용자가 stage에 올린 변경을 기준으로,
AI 에이전트가 커밋 초안을 만들고 안전한 브랜치에서 커밋을 진행하는 기본 흐름을 정의한다.

## 기본 원칙

- stage 범위 선택은 사용자가 직접 한다.
- AI 에이전트는 stage된 변경만 기준으로 커밋 초안을 만든다.
- 커밋 메시지는 AI가 초안을 만들고, 사용자가 검토 및 수정한 뒤 최종본을 전달한다.
- 커밋 전에는 현재 브랜치가 작업 브랜치인지 먼저 확인한다.
- 작업 브랜치가 아니면 브랜치를 먼저 만든 뒤 커밋한다.

## 이력과 커밋 포맷

### 이력 포맷

- 기본 형식: `[주제 or 카테고리] 제목`
- 예시: `[설정] k8s 설정 추가 변경`
- 사용자에게 이력 제목 초안을 제안할 때는 복사하기 쉽도록 코드 블록 안에 담아 보여준다.

### 이력 내용 포맷

- 기본 형식: staged diff 기준으로 핵심 변경 사항을 짧은 bullet로 정리한다.
- 각 항목은 무엇이 바뀌었는지와 왜 필요한지를 드러내도록 쓴다.
- 사용자에게 제안할 때는 이력 내용을 코드 블록 안에 담아 보여준다.
- 예시:
  - k8s 배포 설정 파일을 추가함
  - 환경별 설정 분리를 위해 values 구성을 정리함
  - 기존 배포 흐름은 유지함

### 커밋 포맷

- 기본 형식: `[#이력번호] 이력번호에 해당하는 제목과 동일`
- 예시: `[#13] [설정] k8s 설정 추가 변경`

### 포맷 원칙

- 이력 제목은 주제 또는 카테고리를 앞에 붙여 한 줄로 명확하게 적는다.
- 이력 제목을 사용자에게 제안할 때는 복사와 검토가 쉽도록 코드 블록에 담는다.
- 이력 내용은 staged diff를 기준으로 핵심 변경을 bullet로 요약한다.
- 이력 내용을 사용자에게 제안할 때는 복사와 검토가 쉽도록 코드 블록에 담는다.
- 커밋 제목은 대응되는 이력 번호를 앞에 붙이고, 제목 본문은 해당 이력 제목과 동일하게 유지한다.
- AI 에이전트는 staged diff를 기준으로 이력 제목, 이력 내용, 커밋 제목 초안을 함께 제안할 수 있다.
- 이력번호는 사용자가 확정하기 전까지 AI가 임의로 채우지 않는다.
- 이력번호가 아직 정해지지 않았다면 `[#이력번호]` 같은 자리표시자 형식으로만 제안한다.
- 최종 이력 번호와 최종 문구는 사용자가 확정한다.

## 브랜치 포맷

- 기본 형식: `이력번호-이력제목 영문 소문자 slug`
- 구분자는 `-`를 사용한다.
- 이력 제목을 브랜치명에 옮길 때는 의미가 유지되는 범위에서 영문 소문자 slug로 변환한다.
- 브랜치 분류용 접두어는 사용하지 않고, 이 형식만 기본값으로 사용한다.

예시:

- `13-k8s-config-update`

## 권장 흐름

1. 사용자가 커밋할 파일을 직접 stage에 올린다.
2. AI 에이전트는 stage된 diff를 확인하고 변경 요약과 커밋 초안을 작성한다.
3. 사용자는 초안을 검토하고, 필요하면 이력 제목, 이력 내용, 이력 번호, 커밋 메시지를 다듬어 최종본을 결정한다.
4. AI 에이전트는 현재 브랜치가 작업 브랜치인지 확인한다.
5. 작업 브랜치가 아니면 사용자가 전달한 이력 번호를 기반으로 브랜치를 만든다.
6. 사용자가 커밋을 명시적으로 요청하면 그 메시지로 커밋한다.

## 브랜치 확인 원칙

- 기본 브랜치(`main`, `master`, `develop` 등)에서는 바로 커밋하지 않는 것을 우선한다.
- 현재 브랜치가 작업 브랜치가 아니면 새 브랜치를 만든다.
- 새 브랜치를 만들 때는 `이력번호-이력제목 영문 소문자 slug` 형식을 따른다.
- 이력과의 연결은 브랜치명 안의 이력번호로 식별한다.
- 이력번호가 확정되기 전에는 브랜치명도 최종 확정하지 않는다.

## 커밋 메시지 원칙

- AI가 먼저 초안을 제안한다.
- 사용자가 최종 문구를 검토하고 확정한다.
- 커밋 제목은 짧고 구체적으로 쓴다.
- 필요하면 본문에 변경 이유와 영향 범위를 덧붙인다.
- 커밋 제목은 대응되는 이력 제목과 동일한 본문을 유지한다.
- 이력번호가 정해지기 전에는 커밋 제목도 자리표시자 형식으로만 제안한다.

## 이 workflow가 다루는 것

- staged diff 기반 변경 요약
- 이력 제목, 이력 내용, 커밋 메시지 초안 작성
- 작업 브랜치 여부 확인
- 필요 시 브랜치 생성 후 커밋 진행

## 이 workflow가 다루지 않는 것

- stage 범위 자동 선택
- 사용자 승인 없는 commit/push
- 강제 이력 수정이나 히스토리 재작성
